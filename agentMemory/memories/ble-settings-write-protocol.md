## Status

This is the accepted, working BLE settings protocol for this desktop app as
of 2026-09-03. It is the standard to preserve unless a later hardware or
firmware change is deliberately confirmed and documented.

## BLE settings write

Send two back-to-back ASCII GATT writes to the BLE **Settings
characteristic** (see [[ble-target-uuids]]). Each GATT write is already a
complete message: do **not** append `\r`, `\n`, or `\r\n`.

```
FU1:01:0<brightness>:00:<mode>:0<shootingArea>
FU2:0<shotsHeat>:<secondsHeat>:<HH:mm>
```

Example for brightness 3, Competition mode, shooting area 2, five shots,
40 seconds, and local time 14:07:

```
FU1:01:03:00:0:02
FU2:05:40:14:07
```

- `01`: fixed target/lane number.
- `0<brightness>`: brightness `01`-`05`.
- `00`: fixed battery placeholder in FU1.
- `<mode>`: `0` Competition, `1` Training, `2` OCR; unpadded.
- `0<shootingArea>`: `00`-`02`.
- `0<shotsHeat>`: `01`-`05`.
- `<secondsHeat>`: one of `10`, `20`, `30`, `40`, `50`.
- `<HH:mm>`: current local 24-hour time generated by the desktop app.

The app skips the write when all five settings already equal its latest
confirmed state. Otherwise it sends FU1 then FU2 using GATT write-with-response
and waits up to 10 seconds for an incoming FUK confirmation.

## BLE FUK read

The device reports its actual settings in the shared incoming format:

```
FUK:<targetNumber>:<brightness>:<battery>:<mode>:<shootingArea>:<shotsHeat>:<secondsHeat>:<timestamp>
```

FUK normally arrives as a notification on the BLE **Command characteristic**,
although the desktop app accepts it from either subscribed BLE characteristic.
Incoming chunks are framed on either `\r` or `\n` before parsing.

The desktop settings state uses these fields:

- `brightness` from field 2
- `mode` from field 4
- `shootingArea` from field 5
- `shotsHeat` from field 6
- `secondsHeat` from field 7

`targetNumber`, `battery`, and `timestamp` remain visible in the raw terminal
line but are not stored in `DeviceSettings`.

Every valid incoming BLE FUK—periodic, unsolicited, or write confirmation—
must both remain visible in the BLE terminal and immediately replace the BLE
Settings state. See [[ble-fuk-live-settings-sync]] and
[[settings-write-implementation]].

There is no separate BLE command that requests current settings on connect.
The UI starts from `DEFAULT_DEVICE_SETTINGS` and becomes device-authoritative
when the first valid FUK arrives.
